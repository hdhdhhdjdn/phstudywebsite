# 测试清单（本地 → 线上）

本地版保留且与线上共用同一套前端，**先在本地测通，再推 GitHub 自动部署**。

## 一、本地启动

```cmd
cd /d "C:\Users\lenovo\Documents\deepseek-harness\default-workspace\cuoti-site"
"C:\Users\lenovo\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe" cloud-server.js
```

或直接双击 `启动（班级版）.cmd`。浏览器打开 `http://localhost:8765/`。

## 二、本地功能测试

| 序号 | 操作 | 期望结果 |

| 1 | 注册/登录（第一个账号为管理员） | 进入首页，左侧导航显示 |

## 三、推送到线上

```bash
git add .
git commit -m "更新说明"
git push origin main
```

Vercel 自动构建上线（约 1 分钟）。**数据在 KV/Blob，不受部署影响。**

## 四、线上复测

| 序号 | 操作 | 期望结果 |
|---|---|---|
| 1 | 打开 `https://<项目>.vercel.app` | 页面正常 |
| 2 | 登录（用线上库的账号） | 原有数据都在 |
| 3 | 上传一道新题 → 转文字 → 查看答案 | AI 正常返回 |
| 4 | 手机浏览器打开 | 布局正常、可作答 |
| 5 | 设置 → 备份 | 能下载 JSON |
| 6 | Vercel → Settings → Environment Variables 检查 | KV/Blob 变量已连接 |

## 五、常见坑

- 本地改了 `cloud-data/`（账号、Key、题目）**不会**自动同步到线上；线上数据是独立的。
- 想让线上从空库开始：删除 KV 里 `cuoti:*` 键会清空数据（谨慎）。
- 本地和线上不要混用同一个 Key 文件；Key 都是各自在「设置」里填。
- 线上静态资源缓存很轻，同学一般刷新即可；异常时 Ctrl+F5。
