# 云服务器部署指南（公网访问）

目标：让全班任何时候、任何网络都能打开网站（不再依赖谁的电脑开着）。

---

## 一、买什么

| 项目 | 建议 |
|---|---|
| 厂商 | 阿里云 / 腾讯云（学生机、轻量应用服务器都行） |
| 配置 | **1 核 2G 内存、3M 带宽、40G 硬盘**足够一个班用（图片已压缩到 200–400KB/张） |
| 系统 | **Ubuntu 22.04 LTS**（本指南按它写；Debian 12 也行） |
| 地域 | 离学校近的（华东/华南） |
| 价格 | 学生优惠约 **9–12 元/月**，或首年百元级 |

**关于备案**：
- 用 **IP + 8765 端口**访问 → 一般**不需要备案**，可以先跑起来；
- 想用**域名 + 80/443** → 国内服务器需要 ICP 备案（约 2–3 周），学生项目一般先不折腾。

---

## 二、部署 5 步（大约 15 分钟）

### 第 1 步：放行端口

云厂商控制台 → 你的服务器 → **安全组 / 防火墙** → 放行：

- `TCP 22`（SSH，一般默认开）
- `TCP 8765`（网站）

### 第 2 步：登录服务器

控制台有「远程连接 / 网页终端」，也可以本机 PowerShell：

```powershell
ssh root@你的公网IP
```

### 第 3 步：从 Windows 上传文件

在 `cuoti-site` 目录下打开 PowerShell：

```powershell
powershell -ExecutionPolicy Bypass -File deploy\上传到服务器.ps1 -Server 你的公网IP
```

> 提示：如果提示找不到 ssh/scp → Windows 设置 → 应用 → 可选功能 → 添加「OpenSSH 客户端」。
> 也可以用 WinSCP / FileZilla 手动把 `cloud-server.js`、`index.html`、`login.html`、`css/`、`js/`、`deploy/` 传上去。

### 第 4 步：在服务器上执行部署脚本

```bash
cd /root/cuoti
PORT=8765 REGISTER_CODE=你的邀请码 bash deploy.sh
```

脚本会自动：安装 Node 20 → 复制文件到 `/opt/cuoti` → 注册 systemd 服务（**开机自启 + 崩溃重启**）→ 放行系统防火墙 → 打印访问地址。

> `REGISTER_CODE` 是注册邀请码，**公网部署强烈建议设置**（不设的话任何人拿到地址都能注册）。
> 建议用简单好记的，比如 `class2026`。

### 第 5 步：打开网站

浏览器访问：

```
http://你的公网IP:8765/
```

**第一个注册的账号自动成为管理员**——请先自己注册，再把地址和邀请码发到班级群。

## 三、把现有题库搬上去（可选）

如果本机已经有数据（`cuoti-site/cloud-data/`），直接传上去：

```powershell
scp -r cloud-data root@你的公网IP:/opt/cuoti/
```

然后在服务器上重启服务：

```bash
systemctl restart cuoti
```

或者：本机「设置 → 导出题库包 .zip」→ 云端网站「设置 → 导入」。

## 四、日常运维

| 操作 | 命令 |
|---|---|
| 看日志 | `journalctl -u cuoti -f` |
| 重启 | `systemctl restart cuoti` |
| 停止 | `systemctl stop cuoti` |
| 开机自启 | 已自动设置（`systemctl enable cuoti`） |
| 备份数据 | `cp /opt/cuoti/cloud-data/db.json ~/db-$(date +%F).json` |
| 备份图片 | `tar czf ~/uploads-$(date +%F).tar.gz /opt/cuoti/cloud-data/uploads` |
| 更新代码 | 重新上传 → `systemctl restart cuoti` |

**建议每周备份一次** `db.json` + `uploads/`，下载到本机。

## 五、安全建议（公网必看）

1. **一定要设置 `REGISTER_CODE`**，否则陌生人可注册；
2. 管理员密码用强一点的（别用 1234）；
3. 目前是 **HTTP 明文**，密码在公网上是明文传输的——校内小范围用问题不大；若要更安全，后续可以加 HTTPS（用 Caddy 反代，我可以再帮你配）；
4. 不要把自己的 SSH 密码/私钥发到群里；
5. 定期备份 `cloud-data`。

## 六、常见问题

**Q：浏览器打不开**
- 安全组没放行 8765（最常见）；
- 服务没起来：`systemctl status cuoti`；
- 云厂商的「防火墙」和系统防火墙是两套，都要放行。

**Q：同学打不开**
- 确认给的是**公网 IP**，不是 `192.168.x.x` / `172.17.x.x` 这种内网地址；
- 确认端口是 `:8765`；
- 学校网络限制：一般能访问公网 IP，但如果学校做了端口限制，可换 80/443（需要备案）。

**Q：图片上传失败**
- 检查磁盘：`df -h`；
- 检查目录权限：`ls -l /opt/cuoti/cloud-data/uploads`。

**Q：想换端口**
重新跑一次部署脚本即可：`PORT=9000 REGISTER_CODE=xxx bash deploy.sh`（记得安全组也放行新端口）。

**Q：想加/改邀请码**
重新跑部署脚本并带上新的 `REGISTER_CODE`，会自动覆盖配置并重启。

**Q：数据存在哪**
`/opt/cuoti/cloud-data/db.json`（账号、错题、作答、收件箱）+ `uploads/`（图片）。
