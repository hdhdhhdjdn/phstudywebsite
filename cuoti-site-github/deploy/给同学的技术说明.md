# 错题站 · 服务器技术交接说明

> 给帮忙部署的同学：这是一个**班级共享错题站**（纯前端 + 一个零依赖 Node 服务端），
> 需要一台能跑 Node.js 的服务器。下面是全部要求，按这个做就行。

---

## 一、这是什么

- **前端**：静态 HTML/CSS/JS（无构建步骤、无 npm 依赖）
- **后端**：单文件 `cloud-server.js`（只用 Node 内置模块：http/fs/crypto），**零第三方依赖**
- **数据**：JSON 文件 `cloud-data/db.json` + 图片目录 `cloud-data/uploads/`（不需要数据库）
- **功能**：账号登录/注册、班级共享题库、题目图片上传、作答记录、AI 批改（调用大模型 API）

---

## 二、服务器要求

| 项目 | 要求 |
|---|---|
| 配置 | **1 核 1G 起**，2 核 2G 更稳（一个 50 人班足够） |
| 系统 | Linux（Ubuntu 20.04+/Debian 11+ 推荐）或 Windows Server |
| 磁盘 | 10 GB 足够（图片入库时已压缩到 ~200–400 KB/张） |
| 网络 | 需要**公网 IP**（或域名）；放行 **TCP 8765**（或反代到 80/443） |
| 出网 | 服务器需要能访问外网（AI 批改调用 `open.bigmodel.cn`） |
| 软件 | **Node.js ≥ 18**（推荐 20 LTS；代码用了全局 `fetch`） |
| 数据库 | **不需要** |

> 国内服务器用 `IP:8765` 访问一般**不需要备案**；用域名 + 80/443 才需要。

## 四、部署方式（三选一）

### 方式 A：一键脚本（推荐）

```bash
cd /root/cuoti
PORT=8765 REGISTER_CODE=你的邀请码 bash deploy.sh
```

脚本会自动：安装 Node 20 → 复制到 `/opt/cuoti` → 注册 systemd 服务（开机自启 + 崩溃重启）→ 放行系统防火墙 → 打印访问地址。

### 方式 B：手动

```bash
cd /root/cuoti
PORT=8765 REGISTER_CODE=你的邀请码 node cloud-server.js
```

生产环境建议套 systemd 或 `pm2`。

### 方式 C：Docker

```bash
cd /root/cuoti/deploy
# 改 docker-compose.yml 里的 REGISTER_CODE
docker compose up -d --build
```

## 五、环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `PORT` | 8765 | 监听端口 |
| `HOST` | 0.0.0.0 | 监听地址（公网必须 0.0.0.0） |
| `REGISTER_CODE` | 空 | **注册邀请码，公网部署务必设置**（不设任何人可注册） |

> **AI 批改的 API Key 不在环境变量里**：由管理员登录网页后在「设置 → AI 实时批改」填写，
> 存在 `cloud-data/db.json` 的 `config` 字段（前端只显示掩码）。

## 六、部署后必须检查

1. 浏览器打开 `http://公网IP:8765/`，能看到登录页
2. 注册第一个账号 → 自动成为**管理员**
3. 去「设置」看一眼「存储状态」正常
4. 在「设置 → AI 实时批改」填 Key（智谱 `glm-5.3-flash`，接口 `https://open.bigmodel.cn/api/paas/v4`）后，提交一次作答看能否自动批改
5. 手机/iPad 用同一地址访问一次，确认响应式正常

---

## 七、数据与备份

- 数据目录：`cloud-data/db.json`（账号、错题、作答、配置）+ `cloud-data/uploads/`（图片）
- 备份建议：每天 `tar czf ~/cuoti-backup-$(date +%F).tar.gz /opt/cuoti/cloud-data`
- 迁移：把整个 `cloud-data` 目录拷到新机器同一位置即可
- **只能单实例运行**：JSON 文件存储没有多进程写锁，不要开多个副本/多容器同时写同一目录

---

## 八、安全注意

1. **一定要设置 `REGISTER_CODE`**
2. 管理员密码用强口令
3. 建议给服务加 HTTPS（Caddy 一行反代即可），否则密码是 HTTP 明文
4. 不要用静态服务器直接暴露项目目录（`db.json`、`uploads/` 不能被下载）——现在由服务端白名单控制，只对外提供 `index.html / login.html / css/js`
5. 服务器安全组只放行 22 和 8765（或 80/443）

---

## 九、已知限制

- 单进程 + 内存缓存，30–50 人规模够用（每次改动 120ms 防抖后落盘）
- 没有密码重置功能（忘了只能管理员改 `db.json`）
- AI 批改是"参考判分"，主观题不如老师准确
- 图片走服务器磁盘，注意定期备份
